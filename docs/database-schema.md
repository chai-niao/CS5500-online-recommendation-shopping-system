# Database Schema Design

> AI Hypermarket — CS5500 Final Project

## Overview

The system uses a **dual-database architecture**:

- **PostgreSQL** — Relational data: users, orders, carts, shopping lists, festivals, promotions
- **MongoDB** — Document data: product catalog (with location metadata), chat conversations, user activity logs

---

## PostgreSQL Tables

### Entity-Relationship Summary

```
users ──1:N── user_addresses
users ──1:1── carts ──1:N── cart_items
users ──1:N── orders ──1:N── order_items
users ──1:N── shopping_lists ──1:N── shopping_list_items
festivals (standalone)
promotions (standalone)
```

### `users`

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| id | VARCHAR(50) | PRIMARY KEY | UUID generated by app |
| email | VARCHAR(255) | UNIQUE NOT NULL | Login email |
| password | VARCHAR(255) | NOT NULL | bcrypt hash |
| name | VARCHAR(255) | NOT NULL | Display name |
| phone | VARCHAR(50) | DEFAULT '' | Phone number |
| age_range | VARCHAR(20) | DEFAULT '' | e.g. '25-34' |
| preferred_language | VARCHAR(50) | DEFAULT 'English' | UI language |

| dietary_preferences | TEXT[] | DEFAULT '{}' | e.g. {'Gluten-Free','Organic'} |
| loyalty_tier | VARCHAR(20) | DEFAULT 'Bronze' | Bronze/Silver/Gold |
| loyalty_points | INTEGER | DEFAULT 0 | Accumulated points |
| order_history | TEXT[] | DEFAULT '{}' | Array of order IDs |
| created_at | DATE | DEFAULT CURRENT_DATE | Registration date |

### `cart_items`

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| id | SERIAL | PRIMARY KEY | Auto-increment |
| cart_id | INTEGER | FK → carts ON DELETE CASCADE | Parent cart |
| product_id | VARCHAR(50) | NOT NULL | References MongoDB product.id |
| quantity | INTEGER | NOT NULL DEFAULT 1 | Item quantity |

**Unique constraint:** (cart_id, product_id) — one entry per product per cart.

## MongoDB Collections

### `products`

Stores full product catalog including location metadata. 24 documents.

```javascript
{
  id: "p1",                          // String ID (unique index)
  name: "Organic Salad Mix",
  category: "Produce",               // indexed
  price: 4.99,
  originalPrice: 6.99,
  emoji: "🥗",
  rating: 4.5,
  reviewCount: 128,
  brand: "Green Farm",
  tags: ["organic", "vegan", "gluten-free"],
  dietaryInfo: ["Vegan", "Gluten-Free", "Organic"],
  description: "Fresh organic mixed salad greens...",
  stock: 50,
  loyaltyPoints: 5,
  festivalTags: [],                  // indexed
  featured: true,                    // indexed
  location: {
    aisle: 1,
    section: "A",
    shelf: 2,
    zone: "Fresh"
  }
}
```

**Indexes:**
- `{ id: 1 }` — unique
- `{ category: 1 }`
- `{ featured: 1 }`
- `{ festivalTags: 1 }`
- Text index on `{ name: "text", brand: "text", description: "text" }`

### `chat_conversations`

Stores AI chatbot conversation history per user session.

```javascript
{
  userId: "u1",
  sessionId: "uuid-string",
  messages: [
    { role: "user", content: "Where is the milk?", timestamp: ISODate() },
    { role: "assistant", content: "Organic Whole Milk is in...", timestamp: ISODate() }
  ],
  createdAt: ISODate(),
  updatedAt: ISODate()
}
```

**Indexes:**
- `{ userId: 1 }`
- `{ sessionId: 1 }`

### `user_activity_logs`

Stores user behavior for future analytics and recommendation improvements.

```javascript
{
  userId: "u1",
  action: "view_product",            // view_product, search, add_to_cart, checkout
  data: { productId: "p1" },
  timestamp: ISODate()
}
```

**Indexes:**
- `{ userId: 1, timestamp: -1 }`

## Cross-Database References

Product IDs (e.g. `p1`, `p2`) serve as the link between PostgreSQL and MongoDB:
- `cart_items.product_id` → MongoDB `products.id`
- `order_items.product_id` → MongoDB `products.id`
- `shopping_list_items.product_id` → MongoDB `products.id`

These are **application-level references**, not enforced by foreign keys across databases.
